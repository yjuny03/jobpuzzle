# 면접 준비·세션 생명주기 개선 설계

## 목표

맞춤 분석 하나를 하나의 면접 세션에만 사용하고, 면접을 시작한 뒤에는 준비 목록이 아니라 진행/검토/리포트 흐름에서만 접근하게 한다. 목록과 질문 선택 UI를 일관되게 정리하고, 종료된 면접에는 다시 진입할 수 없도록 서버와 화면 양쪽에서 보장한다.

AI 평가 실패 처리와 평가 프롬프트 변경은 이번 구현 범위에서 제외한다. 세션 34를 포함한 실패 원인은 로그·저장 데이터·코드 경로를 조사해 별도로 보고한다.

## 상태 및 접근 규칙

1. 분석 중인 맞춤 분석은 기존처럼 분석 진행 목록에 표시한다.
2. 분석이 완료되고 활성 회사 맞춤 질문 세트가 생성됐으며 연결된 면접 세션이 없을 때만 `면접 질문이 준비된 맞춤 분석`에 표시한다.
3. 질문을 선택해 세션 생성에 성공하는 순간 해당 질문 세트는 소비된 것으로 본다. 세션 상태가 `CREATED`, `IN_PROGRESS`, `COMPLETED`, `CANCELED` 중 무엇이든 준비 목록에는 다시 표시하지 않는다.
4. `CREATED`와 `IN_PROGRESS` 세션은 진행 중 또는 결과 검토 중 목록에서 접근한다.
5. `COMPLETED` 세션은 리포트에서만 접근한다. 면접 진행 URL로 직접 접근하거나 답변·질문 추가 API를 호출해도 거절한다.
6. 답변 전 취소는 기존 취소 정책을 유지하되, 취소된 맞춤 질문 세트도 재사용하지 않는다.

## 면접 준비 목록

- `답변 평가` 탭을 제거하고 면접 준비 화면을 단일 화면으로 만든다.
- 진행 중 분석, 진행 중 면접, 준비된 맞춤 분석, 결과 검토 중 면접은 각각 독립적으로 최대 5개를 표시한다.
- 항목이 6개 이상일 때만 해당 섹션 아래에 페이지 번호를 표시한다.
- 페이지 이동은 브라우저 새로고침 없이 이미 받아온 목록을 다시 렌더링한다.
- 진행 중 회사 맞춤 면접 카드에는 `분석 결과 보기`를 추가한다.
- 분석 결과 화면에는 조회 컨텍스트를 전달한다. 연결된 세션이 있으면 분석 내용은 보이지만 `질문을 선택하고 면접 시작` 버튼은 표시하지 않는다.

## 질문 선택

최초 질문 선택 모달과 중간 결과의 남은 질문 추가 모달은 같은 정보 구조를 사용한다.

- 질문 본문
- 이 질문의 의도
- 집중 평가 기준
- 체크박스

최소 한 문항 선택 검증과 질문 표시 순서 정책은 유지한다.

## 중간 결과와 종료

- 결과 검토 중 카드의 `중간 결과 확인`으로만 중간 결과 화면에 접근한다.
- 중간 결과 화면에서는 `질문별 결과`, `평가 항목별 점수`만 제공한다.
- `최종 리포트` 탭과 `남은 질문 추가 / 이대로 리포트 확정` 배너를 제거한다.
- 남은 질문 추가가 필요한 경우 면접 진행 화면에서만 제공한다.
- 사용자가 면접 진행 화면에서 `면접 끝내기`를 선택하면 확인 후 세션을 `COMPLETED`로 전환하고 리포트 생성 흐름으로 이동한다.
- 완료 이후 뒤로 가기나 직접 URL 접근으로 면접 진행 화면을 열어도 리포트 상세 화면으로 이동시키며 편집 API는 서버에서 차단한다.

## 서버 변경

- 질문 세트에 연결된 세션 존재 여부를 조회하는 저장소 계약을 추가한다.
- 준비된 맞춤 분석 조회에서 세션이 한 번이라도 생성된 질문 세트를 제외한다.
- 회사 맞춤 모드 사용 가능 여부도 소비되지 않은 활성 질문 세트 기준으로 계산한다.
- 분석 결과 응답에 연결된 세션의 식별자와 상태 또는 `interviewStartAllowed`를 제공해 화면이 임의 추론하지 않도록 한다.
- 완료된 세션에 대한 시작, 답변 제출, 질문 추가는 기존 `isEditable` 검증을 공통으로 사용한다.

## AI 평가 실패 원인 조사

변경 없이 다음 경계를 추적한다.

1. 세션 34의 답변 메시지, AI 호출 로그, 평가 저장 여부
2. AI 공급자 HTTP 실패 여부
3. JSON-06 응답 파싱 및 필수 필드 검증 실패 여부
4. 평가 저장 또는 꼬리질문 저장 트랜잭션 실패 여부
5. `evaluationFailed`가 질문 완료와 다음 질문 이동으로 변환되는 정확한 코드 경로

결과에는 실제 실패 유형, 현재 사용자 경험이 발생하는 이유, 향후 보완 가능한 선택지를 구분해 기록한다.

## 오류 처리

- 소비된 질문 세트로 세션 생성을 다시 요청하면 `INTERVIEW_SESSION_ALREADY_EXISTS` 또는 동등한 도메인 충돌을 반환한다.
- 조회 전용 분석 화면에서 시작 요청이 발생해도 서버가 최종 차단한다.
- 목록 한 섹션의 로딩 실패가 다른 섹션 렌더링을 막지 않도록 섹션별 오류 상태를 표시한다.

## 테스트

- 회사 맞춤 질문 세트가 미사용일 때만 준비 목록에 포함되는 서비스 테스트
- 완료·취소 세션까지 포함해 한 번 사용된 질문 세트가 제외되는 회귀 테스트
- 분석 결과 응답의 시작 가능 여부 테스트
- 완료된 세션의 답변/질문 추가 차단 테스트
- 페이지네이션 순수 함수 또는 DOM 렌더링 테스트
- 최초 질문 선택 모달에 의도와 평가 기준이 포함되는 프런트엔드 테스트
- 중간 결과 화면에 최종 리포트 탭과 확정 배너가 없는 화면 계약 테스트
- 전체 Gradle 테스트 및 애플리케이션 빌드

## 범위 제외

- AI 평가 실패 횟수 또는 이동 정책 변경
- JSON-06 평가 프롬프트 수정
- 목록 화면의 분석 진행률 실시간 폴링
- 최종 리포트 내용 및 리포트 목록 디자인 변경

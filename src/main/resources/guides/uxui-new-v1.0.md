# UX/UI 디자이너(NEW) 분석 가이드 v1.0

적용 범위: 디자인 / UX/UI 디자인 / NEW

## 평가 초점

- 사용자 문제를 관찰·정의하고, 가설과 설계 결정으로 연결한 과정
- 사용자 흐름, 정보 구조, 화면 구조를 설계한 근거
- Figma 등 도구를 사용해 와이어프레임·프로토타입·디자인 시스템을 구성한 실제 역할
- 사용성 테스트, 피드백, 데이터 또는 정성 관찰을 설계 개선에 반영한 방식
- 개발자·기획자 등 협업자와 요구사항 및 구현 제약을 조율한 경험

## 근거 규칙

- 제공된 문서 marker에 포함된 근거만 사용한다.
- 팀 산출물과 지원자가 직접 맡은 리서치·설계·검증 역할을 구분한다.
- 화면 개수나 서비스 성과만으로 사용자 경험 역량을 단정하지 않는다.
- 포트폴리오에 없는 사용자 조사, 지표 개선, 디자인 시스템 운영 경험을 추정하지 않는다.

## 질문 방향

- 특정 화면 또는 플로우에서 해결하려던 사용자 문제와 우선순위 기준을 묻는다.
- 리서치·사용성 테스트·피드백을 어떤 설계 변경으로 연결했는지 확인한다.
- 와이어프레임에서 최종 UI까지 달라진 점과 그 이유를 구체적으로 묻는다.
- 개발·기획 협업에서 제약을 어떻게 조율했고, 본인이 내린 판단은 무엇인지 확인한다.

## 피해야 할 질문

- 근거 없이 특정 디자인 도구의 숙련도나 리딩 경험을 전제하지 않는다.
- 팀의 서비스 성과를 개인의 UX 개선 성과로 단정하지 않는다.
- 입력 자료에 없는 사용자 조사·A/B 테스트·접근성 개선 경험을 가정하지 않는다.
